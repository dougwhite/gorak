# Working on Gorak

Gorak is an early-alpha Python CLI for moving Actian OpenROAD source between a
source database and readable files. This checkout develops the CLI; an OpenROAD
application project is a separate folder containing `gorak.json`.

## Application editing workflow

Read [docs/agent-workflow.md](docs/agent-workflow.md) for the application workflow,
also packaged as the AGENTS.md generated by `gorak new`.

- Run `gorak sync` before editing readable source.
- Edit `.w4gl` scripts/TOML metadata and `.wml` frame layout/events. Track app
  metadata and inherited field-default JSON with the source_format=2 representation.
  Root defaults are authoritative; app and frame layers contain only overrides.
  No XML companions are tracked.
  Migrate legacy projects with `gorak migrate-source` before ordinary sync.
- Require `gorak sync --push` success before `gorak test`. Tests execute database
  source and never imply synchronization. Inspect `git diff` before committing.
- Keep Workbench editors closed during imports. Stop on conflict or failed
  verification. Retain both versions and all recovery artifacts; never bypass
  locks, baselines, target bindings, pending markers, quarantine or revision gates.
- Use a feature branch and publish a PR when requested. Do not merge without the
  owner's instruction. Never commit `.env`, caches, private source or diagnostics
  containing connection identities or credentials.

See [docs/component-editing.md](docs/component-editing.md) for the current observed
editing surface and acceptance limits. New procedures/classes can be authored from
scratch; all eight observed exported types reconstruct from complete readable source. Component deletion pushes
are not implemented. Report unavailable manual acceptance honestly.

## CLI development

Use Python 3.12 and `uv`. After behavior changes run:

```sh
uv run pytest
uv run ruff check .
uv run mypy
```

Use `uv run ruff format` on changed Python files. Keep the README short; command
reference belongs under `docs/`. Update focused tests and corresponding docs for
behavior changes. Parser changes need parser/fixture coverage. Backend tests must
mock external services; never make real SSH, SCP, ODBC or OpenROAD calls from the
unit suite. Live acceptance uses an explicitly authorized disposable environment.

Keep CLI handlers separate from domain logic. Main areas:

- `parser.py`, `field_defaults.py`: readable source projection and inheritance.
- `portable_source.py`, `component_edits.py`, `wml_writer.py`, `defaults_writer.py`:
  legacy migration overlays. `readable_source.py`, `readable_values.py` and
  `readable_markup.py` implement complete readable reconstruction. `xml_shapes.py` supplies observed schema ordering/types.
- `importer.py`, `import_backend.py`, `push.py`: verified compiled source imports.
- `safe_pull.py`, `sync_plan.py`, `sync_guard.py`: pull planning and safety.
- `runner.py`, `run_backend.py`: application and configured test execution.
- `remote_scripts/`: packaged Windows helpers, currently version 8. Keep a single
  packaged helper source and use `gorak remote install` after helper changes.
- `writer_worker.py`, `writer_launch.py`: managed writers and generated zipapp.
- Revision checkpoints, journal snapshots/ancestry/observers, native source and
  encoded-source decoding are existing specialist paths. Preserve their contracts
  and safety tests; ordinary XML fallback does not replace or disable them.

Read the relevant revision/journal/native-source documentation before changing
those subsystems. No direct SQL writes as a workaround for a rejected source push.
Unknown XML layouts must retain a safe fallback or explicit refusal.

Inspect the working tree before changes and before commits. Leave unrelated local
files alone. Do not publish private application/corpus identifiers, machine names,
source database identities, credentials, runtime logs or copied proprietary source.
Use neutral synthetic fixtures and examples. Do not force-push or discard work.
